# リザルト遷移・敵HP初期化

## 変更内容

- PlayerHealth.OnDied：HP0で一度だけ発火する死亡イベント。
- StageCountDownTimer.OnTimeUp：既存の時間切れイベントを使用。シーンの制限時間は200秒。
- StageResultController：両イベントを購読し、LateUpdateで結果確定。死亡はFailure、時間切れはSuccess。同じフレームなら死亡優先。シーン遷移は一度だけ。
- GameRunResult：結果をResultシーンへ受け渡す。新しいプレイで結果とスコアを初期化。
- ResultScreenController：「成功」「失敗」の日本語表示とタイトルボタン。Result単独起動時は「リザルト」と表示。
- Resultシーン：Canvas、GraphicRaycaster、Input System対応EventSystem、日本語TMPフォント、タイトルボタンを配置・接続。
- TimeDilationController：終了時・無効化時にスローと物理更新間隔を復元。
- EnemyBase：Awakeで直置きの敵HPを初期化。Spawn時もHPをリセットしOnSpawnedを呼ぶ。TurretEnemyBaseはbase.Awakeを呼ぶ。死亡処理の多重実行も防止。
- 回避中の反撃は現行仕様として維持。攻撃禁止処理は追加していない。

## Playモードでの確認

| ケース | 結果 |
| --- | --- |
| 敵5体の開始時HP | 砲台3/3、誘導砲台2体は各5/5、連射砲台5/5、追尾機3/3 |
| 敵へ1ダメージ、その後Spawn | HPが1減り、再Spawnで最大HPへ戻る |
| プレイヤーへ致死ダメージ、続けてDieと追加ダメージ | 死亡イベントは1回のみ |
| スロー中に死亡 | Resultへ遷移し「失敗」、timeScale=1、fixedDeltaTimeは約0.02へ復元 |
| タイトルボタン | UIレイキャストでボタンが最前面にヒット。PointerClickイベントからTitleへの遷移を確認 |
| 次のゲーム開始 | 前回結果None、スコア0へリセット |
| スロー中に時間切れ | Resultへ遷移し「成功」、時間倍率を復元 |
| 同一フレームにOnTimeUp→死亡 | Resultの結果はFailureとなり「失敗」を表示 |
| リザルトの入力基盤 | EventSystemは1つ。文字・ボタンは有効、非ゼロサイズ |
| コンパイル | 成功 |
| 動作検証中のゲームコード例外 | 確認した区間ではなし |

時間切れテストは、保存済み設定が200秒であることを確認後、Playモードの残り時間だけを短縮して本来のタイマーUpdateからOnTimeUpを発火させた。200秒の実時間完走やPlayerビルドは今回未実施。

検証の初期にGameビューが存在せずフレーム更新・撮影が進まない状態があり、Gameビューを開いて確認を続行した。Consoleにはこの撮影コマンド失敗のエラーが残るが、ゲームコードの例外ではない。ユーザーのConsole履歴は消去していない。

## レビュー後の調整

- クラス・処理メソッドのsummaryを既存の複数行形式に統一し、引数の説明を追記。
- 今回の対象クラスをpublicメソッド→Unityライフサイクル→内部処理の順に整理。派生クラス向けprotectedメソッドもライフサイクルの後に配置。
- ResultScreenControllerにSerializeFieldのSuccess Text / Failure Text / Default Textを追加。
- Inspector相当のSerializedObject経由で「任務達成」「作戦失敗」「結果待ち」を設定し、3通りの表示処理を確認。検証後は「成功」「失敗」「リザルト」へ復元して保存。
